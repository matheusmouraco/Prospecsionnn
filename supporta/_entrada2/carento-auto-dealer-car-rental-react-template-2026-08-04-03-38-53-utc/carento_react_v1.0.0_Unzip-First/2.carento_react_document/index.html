Next.js Compatibility Shims

To avoid rewriting JSX in all 60+ components, three small wrappers are shipped that mirror the API of next/link, next/image and next/dynamic. The migration script points every next/* import at these shims.

  • src/components/common/Link.tsx — renders <Link> from react-router-dom for internal routes, falls back to plain <a> for external URLs / hash / mailto: / tel:.
  • src/components/common/Image.tsx — renders a plain <img>, silently accepting every prop of next/image (priority, fill, sizes, blurDataURL, quality, unoptimized, …).
  • src/util/dynamic.tsx — wraps React.lazy + <Suspense> and accepts next/dynamic's { ssr, loading } options.

Routing

The template uses React Router v7 (createBrowserRouter) for client-side routing. Because every page was shimmed to use the custom @/components/common/Link wrapper, the existing JSX (<Link href="/cars-list-1">...</Link>) keeps working unchanged — the wrapper converts the href prop to React Router's to at render time.

Route mapping (auto-generated from the Next.js app/ directory):

  • / → src/pages/Home.tsx
  • /about-us → src/pages/AboutUs.tsx
  • /cars-list-1 → src/pages/CarsList1.tsx
  • /cars-details-1 → src/pages/CarsDetails1.tsx
  • * (catch-all) → src/pages/NotFound.tsx

Migration Scripts

Two Node scripts live in scripts/ and are useful if you ever need to re-generate pages from an updated Next.js source.

  • scripts/generate-pages.mjs — reads the sibling Next.js project (default path: ../1.carento_nextjs_template/app) and:
    • Copies app/page.tsx → src/pages/Home.tsx, route /.
    • Copies app/<slug>/page.tsx → src/pages/<PascalCase>.tsx, route /<slug>.
    • Copies app/404/page.tsx → src/pages/NotFound.tsx, route *.
    • Writes src/router.tsx with all imports and route entries.
  • scripts/migrate.mjs — walks every .ts/.tsx under src/ and performs text rewrites:
    • from "next/link" → from "@/components/common/Link"
    • from "next/image" → from "@/components/common/Image"
    • from "next/dynamic" → from "@/util/dynamic"
    • Removes the "use client"; directive at the top of files (no-op in a React SPA).
    • Warns when files still import next/navigation, next/router, or next/font — these require manual review.

Run order (first time, or when the Next.js source has new pages):

                                    npm run generate-pages
                                    npm run migrate

Development

How to start this project:

  • Step 1: Extract the zip file you downloaded from ThemeForest.
  • Step 2: Open Folder 2.carento_react_template with a code editor (such as VS Code)
  • Step 3: Run the command: npm install
  • Step 4: Then, run the command: npm run dev (Vite dev server with HMR)
  • Step 5: To create a production build: npm run build (output in dist/)
  • Step 6: To serve the production build locally: npm run preview

Your project will be opened at: http://localhost:3000

Deployment

The production build is a static dist/ folder — you can host it on any static host: Vercel, Netlify, Cloudflare Pages, GitHub Pages, Firebase Hosting, AWS S3 + CloudFront, or any traditional web server (Apache, Nginx, IIS).

Vercel / Netlify / Cloudflare Pages — easiest path:

  • Push your project to a Git provider (GitHub, GitLab, BitBucket).
  • Sign up at vercel.com / netlify.com / pages.cloudflare.com.
  • Import the repository. Build command: npm run build. Output directory: dist.
  • Important (SPA fallback): because the app uses createBrowserRouter, every non-root URL (/about-us, /cars-list-1, …) must fall back to index.html. All three providers handle this automatically when they detect a Vite app. On a custom server, add a rule like:
                                    # Nginx
                                    location / {
                                        try_files $uri $uri/ /index.html;
                                    }

                                    # Netlify _redirects
                                    /*    /index.html   200

                                    # Vercel vercel.json
                                    { "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }

Learn more: https://vite.dev/guide/static-deploy.html
